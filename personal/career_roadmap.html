공고에서 역산한 요구사항

2026.07 기준 타겟 9개사 + 인접 스타트업의 실제 채용 공고를 직접 열어 뽑은 요구사항이다. 아래 표가 이후 모든 Phase의 설계 근거 — 각 Step은 "하면 좋아서"가 아니라 "이 공고가 요구해서" 존재한다. 공고는 빠르게 바뀌므로 지원 시점(2027)에 각사 채용 페이지로 재확인.

학위 불안, 데이터로 종결. 직접 열어본 개발·애플리케이션 트랙 공고에서 석사를 필수로 요구한 곳은 0건이다. 업스테이지 AI Agent Engineer는 명시적으로 "학력 무관", 백엔드·플랫폼·Document AI·데이터 공고 모두 학위 요건 미기재. 석사가 필수인 것은 전문연구요원(병역특례)·파운데이션 모델 리서치 트랙(논문 실적 요구)뿐이다. 애플리케이션 트랙에서 학위는 요건이 아니라 실무 포트폴리오로 대체된다 — 즉 Phase Ⅱ의 프로젝트가 곧 학위 대체재.

딥 프로젝트 하나

프로젝트는 딱 하나 — 순수 RAG가 아니라 법령·규정 QA "에이전트". 실제 공고가 RAG를 넘어 Agent·Tool Use·Function Calling을 자격요건으로 요구하기 때문(업스테이지 AI Agent, 뤼튼·라이너 ML). 각 컴포넌트를 먼저 프레임워크 없이 직접 구현해 원리를 손에 넣고, 그다음 LangGraph로 재구현한다.

원칙 · 공고 근거로 교정

  • 프로젝트는 딱 하나. 여러 개 벌리지 않는다.
  • 먼저 직접 구현 → 그다음 LangGraph로 재구현, 둘 다 한다. 기존 계획의 "LangChain 쓰면 0점"은 공고와 배치된다 — 업스테이지 AI Agent Engineer 자격요건에 "LangChain, LangGraph 등 Agentic Workflow 프레임워크 경험", 제논·인터엑스·뤼튼도 우대로 명시. 정답은 "직접 짜봐서 내부를 알고 + 프레임워크도 능숙"이다. 인터뷰 만점 답변 = "리트리버를 직접 짜며 X 때문에 Y로 설계했고, 프로덕션은 LangGraph로 옮기며 트레이드오프를 이렇게 봤다".
  • Claude Code 등 AI 도구 사용 OK. 단 철칙 — 각 컴포넌트를 화이트보드에 그려 남에게 설명할 수 있을 때까지 다음으로 넘어가지 않는다. AI가 짠 코드에서 비효율·오류를 최소 1개씩 직접 찾아 수정하고 커밋 메시지에 기록한다.

프로젝트 주제 · 하나 선택

구현할 컴포넌트 · 각 항목 = 어느 공고 요구사항

→ 뒤 회사명은 그 컴포넌트를 자격요건/우대로 실제 명시한 공고다. 인터뷰에서 이 매핑을 그대로 근거로 쓴다.
