AI 영상 생성 서비스

모델은 전체 그림에서 보라색 상자 하나뿐이다. 나머지는 전부 그 모델을 안전하게, 그리고 적자 없이 돌리기 위한 레이어다. 가중치 안에는 콘텐츠 필터가 없다. 제한은 서빙 레이어의 붉은 상자 네 개가 맡는다.

전체 아키텍처

심사 · 필터 (붉은 상자 4개) 추론 (모델은 굵은 테두리 하나) 전달 공통 인프라 점선 화살표는 제어·부가 신호

핵심 명제 세 가지

모델은 상자 하나

  • 보라색 "GPU 워커 풀"이 유일한 생성 지점. 나머지 12개 상자는 전부 그걸 둘러싼 레이어.
  • 오픈소스 가중치(Wan, LTX, HunyuanVideo)를 받으면 생성 자체는 하루 만에 된다.

제한은 서빙 레이어가 한다

  • 가중치 안에는 필터가 없다. 텍스트·이미지 입력, 영상·워터마크 출력 — 붉은 상자 4개가 전부 바깥에 있다.
  • xAI Grok이 2026년 초 사실상 다시 세운 것도 이 부분이었다.

공수는 필터와 GPU 비용에서

  • 개발·운영 시간의 대부분은 분류기 임계값 튜닝, 과잉차단·누락 수집, 콜드스타트와 양자화에 쓰인다.
  • 모델 성능 차이보다 분당 GPU 단가가 손익을 가른다.

단계별 설명

1. 클라이언트 → API 게이트웨이

  1. 요청을 받으면 바로 처리하지 않고 작업 ID만 발급하고 큐에 넣는다.
  2. 게이트웨이: 인증(JWT/세션), 레이트 리밋, 크레딧 잔액 확인과 선차감, 요청 로깅.
  3. 사용자 DB: 계정, 크레딧, 결제 이력, 생성 이력. 실패 시 환불도 여기서.

2. 입력 심사 (생성 전)

  1. 텍스트 1단계: 정규식·사전 금칙어. 싸고 빠름, 명백한 것만.
  2. 텍스트 2단계: 소형 분류 모델로 카테고리 점수 (성적·폭력·미성년·실존 인물·정치). 후보: OpenAI Moderation, Llama Guard, ShieldGemma, 직접 튜닝한 DeBERTa.
  3. 애매 구간은 거부 대신 순화 프롬프트로 재작성하는 서비스가 많다.
  4. 이미지(I2V일 때): 얼굴 검출 → 유명인 임베딩 대조, 연령 추정, NSFW 분류.
  5. 실무 난점: 한국어 대응과 임계값 튜닝.

3. 작업 큐

  1. 영상 한 건에 수십 초~수 분, GPU 메모리 통째 점유 → 동기 응답 불가.
  2. Redis(BullMQ/Celery), RabbitMQ, SQS.
  3. 우선순위(유료 티어 먼저), 재시도, 타임아웃, 데드레터 큐.

4. GPU 워커 풀

  1. 모델은 워커 기동 시 1회 로드 후 상주. 요청마다 로드하지 않는다.
  2. 실행 방식: ① Diffusers 파이프라인을 파이썬으로 래핑(표준) ② ComfyUI 헤드리스 — 워크플로 JSON을 API로 ③ Triton 등 추론 서버(배치, 프로덕션).
  3. 모델 저장소: 가중치·LoRA를 네트워크 볼륨(또는 S3 + 로컬 캐시)에. 없으면 워커가 뜰 때마다 수십 GB 다운로드 → 콜드스타트 수 분.
  4. 오토스케일러: 큐 길이 기준. RunPod Serverless·Modal은 0대까지 축소 가능하나 콜드스타트 1~2분 → 최소 1대 상시 유지로 타협. 자체 클러스터면 K8s + KEDA.

5. 출력 심사 (저장 전)

  1. 전 프레임 검사는 비쌈 → 초당 1프레임 샘플링 → 이미지 NSFW·폭력 분류기(CLIP 기반 또는 전용).
  2. 한 프레임이라도 임계값 초과 시 전체 반려. 프롬프트는 정상인데 모델이 엉뚱하게 그린 경우를 여기서 잡는다.
  3. 워터마크: 보이지 않는 마크(SynthID 계열) + C2PA 메타데이터. EU AI법·한국 AI기본법 모두 표시 의무 방향 → 선택이 아닌 필수.

6. 전달 · 운영

  1. S3 호환 스토리지 → CDN → 만료 시간이 있는 서명된 URL. 보관 정책(예: 7일 후 삭제).
  2. 완료 알림: 작업 ID 폴링, 웹소켓/SSE, 모바일 푸시.
  3. 감사 로그: 프롬프트·심사 점수·결과·사용자 ID 전부 보관. 신고 → 사람 검토 큐.
  4. 과잉차단(false positive)과 누락(false negative)을 양쪽 다 모아 분류기 재학습 → 운영의 핵심 루프.

GPU 비용 계산기

월 생성 건수와 GPU·모델 조합을 바꿔 보면서 직접 호스팅 원가와 fal.ai 위탁 원가가 어디서 교차하는지 확인할 수 있다. 상시 워커 수를 0으로 두면 완전 서버리스(콜드스타트 감수), 1 이상이면 그만큼 24시간 켜 둔다.

모델 외 서비스 레이어 체크리스트

계정

인증, 성인 인증(필요 시), 약관 동의. 생성 이력은 사용자에게도 보여 주고 감사 로그에도 남긴다.

과금

크레딧 선차감, 실패·반려 시 자동 환불, PG 연동. 반려된 건을 환불할지 말지는 약관에 명시.

제한

레이트 리밋, 동시 생성 수, 티어별 해상도·길이. 무료 티어는 480p·5초·디스틸 모델로 묶으면 GPU 원가가 1/10.

심사

입력 필터, 출력 필터, 카테고리별 임계값, 재작성 전략. 한국어 금칙어 사전은 직접 만들어야 한다.

표시

보이지 않는 워터마크, C2PA, 이용약관 내 AI 생성 고지. 다운로드 파일에도 메타데이터가 살아 있어야 한다.

운영

감사 로그, 신고 처리 SLA, 사람 검토 큐, 분류기 재학습 주기. 과잉차단 민원도 데이터다.

비용

오토스케일 정책, 콜드스타트 대책(상시 1대 + 모델 캐시 볼륨), 양자화, 가동률 모니터링.

규제

구축 순서

  1. RunPod에 ComfyUI 템플릿 → API 모드 호출Wan 2.2 5B 또는 LTX-2 FP8을 4090 Pod에 올리고 워크플로 JSON을 HTTP로 던져 본다. 구조 체감이 목적.
  2. 모델 캐시 볼륨 + 상주 워커네트워크 볼륨에 가중치를 두고 워커 기동 시 1회 로드. 콜드스타트가 수 분에서 수십 초로 준다.
  3. 큐 + 스토리지 + 작업 ID APIRedis 큐, S3 서명 URL, 작업 상태 폴링 엔드포인트. 여기까지가 "돌아가는 서비스"의 최소 단위.
  4. 입력 심사금칙어 사전 → Llama Guard/ShieldGemma 분류 → 재작성. I2V면 얼굴·연령 검사 추가. 임계값은 일부러 높게 시작해 과잉차단 쪽으로.
  5. 출력 심사 + 워터마크초당 1프레임 샘플링 NSFW 분류, C2PA 메타데이터 삽입. 반려 건은 환불 처리와 함께 로그로.
  6. 과금 · 크레딧 · PG선차감과 실패 환불이 큐 재시도와 꼬이지 않게 멱등 키로 묶는다.
  7. 오토스케일 + 최적화큐 길이 기준 스케일, FP8·TeaCache·디스틸 LoRA 적용. 가동률 대시보드를 붙여 서버리스/온디맨드 비율을 조정.
  8. 감사 로그 · 신고 · 사람 검토공개 전 반드시. 신고 접수 창구와 검토 큐가 없으면 앱스토어·PG 심사에서 막힌다.
