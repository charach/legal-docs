해외 공인 스타트업 레이더

17개국의 투자 보도, 정부·액셀러레이터 공인 명단, 피칭·해커톤 수상작만 모아서 한국에 없는데 될 만한 아이디어를 찾는다. 집에 있는 Mac mini가 매주 월요일 새벽에 혼자 수집하고 로컬 LLM으로 거른다. 나는 아침에 폰으로 시트를 열어 볼 만한 것에 체크만 한다.

확정된 결정

설계 전에 질문으로 정한 것들. 이후 설계는 전부 이 표를 전제로 한다.

항목결정
실행 환경집의 Mac mini M1 · 16GB, 하루 종일 켜져 있음. launchd가 자동으로 깨운다. 사람이 실행하는 단계는 없다
코드 위치별도 비공개 레포 (startup-radar). 이 사이트에는 설계 페이지만 남기고, 설계 원본 md(portfolio/startup_radar_design.md)는 새 레포로 옮겨 거기서 이어간다. DB·로그·키는 레포에도 넣지 않는다
처리 범위최초 실행 때 최근 12개월치를 DB에 적재만 한다 (LLM을 거치지 않음). 매주는 최신 1주일치만 거르고 시트에 올린다
LLM로컬 Ollama가 기본 (비용 0). 품질이 모자란 단계만 Claude API로 바꿀 수 있게 설정으로 분리 (§8)
paywall=partial피드의 제목·요약만 보관하고 원문 페이지는 열지 않는다. DealStreetAsia(paywall=y)도 같은 방식의 예외로 허용
signalfunding_db는 보존 (accredited와 같은 취급). report(KOTRA)는 수집하지 않고 수동 참고만
KR 소스한국 유사 서비스를 찾는 비교 인덱스로만 쓴다. 검토 화면에는 나오지 않는다
funding_news 폐기금액·라운드·투자사가 모두 확인되지 않을 때만 폐기 (하나라도 있으면 보존)
해커톤 수상작참가 등록자 수나 총상금이 임계값을 넘는 대회의 수상작만. 값은 설정 파일

1전체 아키텍처

내가 손대는 부분 Mac mini에서 자동으로 도는 부분 선택 (기본은 꺼짐)

원칙

  • 프로세스는 하나다. radar run이라는 CLI가 전부 한다. 큐·워커·서버·컨테이너는 없다.
  • 상태 기반으로 이어서 한다. 각 단계는 "자기 입력 상태인 행"만 집어 처리한다. 정전이나 재시동으로 중간에 끊겨도 다음 실행이 이어서 한다.
  • 바뀌는 건 설정 파일이다. 소스가 수백 개로 늘어도 바뀌는 것은 sources.csv와 adapters.yaml이다.
  • 의존성은 최소한으로 한다. requests, feedparser, PyYAML, beautifulsoup4, gspread 다섯 개. Ollama는 HTTP로 부르므로 SDK가 필요 없다. Claude API를 켤 때만 anthropic을 추가한다. SQLite(FTS5 포함), robots.txt, 로그, 메일은 표준 라이브러리로 처리한다. 헤드리스 브라우저는 넣지 않는다.

세 가지 흐름

매주 자동 · 월 03:00 ~ 06:00경

  1. launchd가 radar run을 깨운다. 이번 주 사이클이 이미 끝났으면 바로 종료한다.
  2. 지난주 시트의 ☑·메모를 DB로 회수한다.
  3. 대상 소스를 수집하고 중복을 지운 뒤 최근 7일 것만 남긴다.
  4. 규칙으로 1차 폐기하고, 로컬 LLM이 추출·분류한다. 그다음 판정하고 한국 유사 서비스와 비교한다.
  5. 시트의 '이번 주' 탭을 새로 쓰고, 맨 위에 실행 요약 한 줄을 남긴다.

최초 1회 · 설치 날

  1. Mac mini에 레포를 clone하고 Ollama와 모델을 설치한 뒤 radar doctor로 점검한다.
  2. radar backfill: 12개월치 공인 명단·수상작·피드 과거 페이지를 DB에 적재만 한다. LLM은 거치지 않는다. 몇 시간에서 하루 정도 걸리고, 끊겨도 이어서 한다.
  3. KR 소스의 12개월치가 그대로 한국 비교 인덱스가 된다.
  4. radar install로 launchd를 등록하면 그다음부터는 자동이다.

내가 하는 일

  1. 월요일 아침에 폰에서 시트의 '이번 주' 탭을 연다.
  2. 볼 만한 회사에 ☑를 하고, 필요하면 메모를 남긴다.
  3. 체크한 것은 다음 실행 때 '관심' 탭에 쌓인다.
  4. 가끔 소스를 추가한다. sources.csv에 한 줄을 넣고 push하면 다음 사이클 시작 때 반영된다.

자동 실행 · Mac mini

설치가 끝나면 사람이 실행할 일은 없다. crontab과 같은 역할을 macOS의 launchd가 맡는다. 매일 03:00과 부팅 직후에 radar run을 깨우고, 스크립트는 "이번 주(월요일 시작) 사이클이 끝났는가"만 본다. 평소에는 월요일 03:00에 한 번 돌고, 나머지 날은 확인만 하고 바로 끝난다. 월요일에 정전이나 업데이트로 꺼져 있었다면 켜진 직후나 다음 날 03:00에 밀린 사이클을 돈다.

launchd (채택)cron
놓친 실행잠자기 중에 놓친 실행은 깨어날 때 1회 실행한다. 부팅 직후 1회(RunAtLoad)도 가능놓친 실행은 그냥 건너뛴다
macOS 권한사용자 에이전트라 추가 권한이 필요 없다폴더에 따라 cron에 전체 디스크 접근 권한을 줘야 한다
로그stdout/stderr 파일 경로를 지정할 수 있다로컬 메일로 간다 (따로 설정 필요)
등록radar install이 plist를 만들고 등록한다crontab -e 한 줄

Mac mini는 상시 켜져 있어서 둘의 차이가 작다. 다만 정전이나 업데이트로 재시동된 뒤 스스로 복구하는 것은 launchd가 더 깔끔하다. 같은 시각에 두 개가 겹쳐 돌지 않도록 잠금 파일(PID 기록)을 쓰고, 실행 중 잠자기를 막도록 caffeinate -i로 감싼다. 주간 사이클을 시작할 때 git pull --ff-only로 코드와 설정을 갱신하고, 실패하면 현재 버전으로 계속 돌며 로그를 남긴다.

Mac mini 준비 체크리스트

잠자기 끄기

시스템 설정 → 에너지에서 자동 잠자기 방지를 켠다 (pmset sleep 0). 디스플레이만 꺼지는 것은 상관없다.

정전 후 자동 시동

"정전 후 자동으로 시동"을 켠다 (pmset autorestart 1).

자동 로그인

launchd 사용자 에이전트와 Ollama는 로그인 세션 안에서 돈다. FileVault가 켜져 있으면 자동 로그인이 안 되므로 재시동 후 한 번 직접 로그인해야 한다 (열린 질문 1).

원격 로그인 (SSH)

노트북에서 ssh mini radar status로 상태를 확인하고 문제를 고친다.

Ollama

brew install ollama와 brew services start ollama로 상시 실행한다. 모델은 하나만 받아 두고, 동시 처리 1개·컨텍스트 8K로 둔다.

OS 업데이트

보안 업데이트만 자동으로 받는다. 재시동이 필요한 업데이트는 월요일 새벽을 피한다.

2데이터 모델

소스 설정 · config/sources.csv

기존 12개 열은 그대로 두고 3개만 더한다.

추가 열의미
source_id고정 키 (예: crunchbase-news, gnews-ko-funding). DB가 이 값으로 소스를 알아보므로 이름을 바꿔도 이력이 유지된다
scope비워 두면 paywall에서 정해진다: n→full, partial→feed_only, y→skip. 예외는 직접 적는다 (DealStreetAsia = feed_only)
adaptercrawl·api 소스가 쓸 어댑터 이름 (devpost, list_diff_html …). rss·gnews는 비워 둔다

수집 대상 = active=y · tier ≤ max_tier(처음은 1) · fetch_type ≠ manual · signal ≠ report · scope ≠ skip · 자동 비활성 아님 · (rss/gnews라면) 피드 검증 통과. feed_only인데 피드가 없는 소스(더브이씨, STARTUP DB News, Fortune Term Sheet)는 수집할 길이 없어 제외되고 로그에 남는다.

원문 1건에서 회사가 여러 곳 나올 수 있다 (주간 투자 라운드업 기사, 수상자 목록). 그래서 items와 mentions를 나눴다. 한국 비교 인덱스를 따로 만들지 않고 KR 소스 원문의 전문 검색으로 대신한다. KR 원문은 이미 한국어라 LLM을 거칠 필요가 없고, 12개월 적재분이 그대로 인덱스가 된다.

signal 보관 방식 (3단)

  1. items.signal: 수집 시점의 소스 signal을 복사해 둔다. 나중에 CSV를 고쳐도 과거 근거는 그대로 남는다.
  2. mentions: evidence_quote(원문을 그대로 인용한 구절)와 투자·수상 필드가 그 signal이 실제로 확인됐다는 기록이다. 폐기 규칙은 이 필드만 보고 코드가 판정한다.
  3. companies.signals: 회사에 붙은 모든 signal의 집합. 시트에는 accredited: YC W26 · funding_news: Series A $12M (Crunchbase News)처럼 근거가 쌓여 보인다.

최근 1주일 창

매주 다루는 것은 event_at이 최근 7일 안에 든 항목뿐이다. event_at은 뉴스라면 게시일이다. 목록·수상작처럼 날짜가 없거나 늦게 발표되는 항목은 처음 본 날이다 (예: 3주 전에 끝난 해커톤의 수상작이 이번 주에 공개되면 이번 주 항목). 사이클을 몇 주 놓쳤어도 처리하는 건 최신 7일치뿐이다. 나머지는 archived로 남아 검색으로만 볼 수 있다.

중복 제거

  • 기사 단위 (LLM 전): 정규화한 URL이 같으면 중복이다. 정규화는 소문자화, www.·m.·AMP 경로 제거, utm_*·fbclid·gclid·ref 제거, 쿼리 정렬, 프래그먼트와 끝의 / 제거로 한다. 정규화한 제목이 같고 게시일이 3일 안이어도 중복이다 (Google News가 다른 매체 기사를 다시 실어 오는 경우). 대표 기사는 tier가 높고 본문이 있는 쪽으로 고른다.
  • 회사 단위 (LLM 후): 사이트의 등록 도메인이 같으면 같은 회사다. 도메인이 없으면 회사명 키로 비교한다. 회사명 키는 NFKC → 소문자 → 법인 접미사 제거(Inc, Ltd, GmbH, SAS, BV, Oy, AB, Pte, 株式会社, 有限公司, (주) …) → 공백·구두점 제거로 만든다. 이름이 같아도 양쪽 도메인이 서로 다르면 다른 회사로 본다. 잘못 묶인 것은 aliases.yaml에 한 줄로 바로잡는다.

5fetch_type별 수집 방식

공통 · 수집 예절 (http)

User-AgentStartupRadar/0.1 (personal research; +https://ttomstudio.com/portfolio/startup-radar-architecture.html). 연락처로 이메일 대신 이 페이지를 적는다
robots.txt호스트별로 24시간 캐시한다. 4xx면 전부 허용으로 본다. 5xx나 타임아웃이면 이번 실행에서 그 호스트를 건너뛴다. 금지된 경로는 요청하지 않고 robots_blocked로 기록한다. Crawl-delay를 따른다
간격같은 호스트는 최소 3초, 크롤링 어댑터는 5초. 다른 호스트끼리는 기다리지 않는다
타임아웃·재시도연결 10초, 읽기 20초. 5xx와 타임아웃은 최대 2회 지수 백오프로 재시도한다. 429는 Retry-After를 따르되 60초가 넘으면 이번 실행에서 포기한다
조건부 GET피드는 ETag와 If-Modified-Since를 보낸다. 304는 성공으로 친다
유료skip이면 요청하지 않는다. feed_only면 피드 URL이 아닌 요청을 http가 직접 거부하므로, 어댑터가 실수해도 원문은 열리지 않는다

소스가 수백 개가 돼도 순차 처리로 충분하다. 다른 호스트끼리는 대기가 없기 때문이다. 같은 호스트(news.google.com)에 쿼리가 많아져도 3초 간격이면 100개에 5분이다.

fetch_type방법
rss조건부 GET으로 받아 feedparser로 읽는다. link는 url, guid는 external_id, summary는 HTML을 지운 2,000자, published는 게시일이 된다. 엔트리가 0개이거나 파싱에 실패하면 실패로 센다. 본문 보강(원문 읽기)은 기본으로 꺼 둔다. 12개월 적재: 피드 첫 페이지에는 최근 글만 있다. WordPress 피드는 ?paged=2,3…을 지원하는 곳이 많아, 적재 때 12개월 전에 닿거나 실패할 때까지 페이지를 넘긴다. 지원하지 않는 피드는 지금 보이는 만큼만 적재한다.
gnewsrss와 같고, 제목 끝의 - 매체명을 떼어 출처로 둔다. 링크는 Google 리다이렉트라 풀지 않는다. 중복은 제목 키로 판정하고 원문은 열지 않는다. 복제는 CSV에 한 줄을 추가하면 된다. radar sources add-gnews --country DE --lang de --q "Startup Finanzierungsrunde"가 URL을 조립해 행을 넣어 준다. 12개월 적재는 할 수 없다 (최근 약 100건만 나옴).
api범용 JSON 어댑터. adapters.yaml에 URL 템플릿, 결과 배열 경로, 필드 매핑, 페이지 넘김 방식을 적으면 코드 없이 추가된다. 로그인이나 키가 필요한 API는 manual로 돌린다.
crawl어댑터는 세 종류다 (아래 표). 사이트 구조가 바뀌면 오류 없이 0건이 나오므로, 전에 1건 이상이던 소스가 2회 연속 0건이면 실패로 센다. 어댑터마다 실제 응답 1개를 테스트 fixture로 저장해 둔다.

7feed_url 검증 절차

radar verify [--all | --id …] [--apply]: 새로 추가된(unverified) 소스는 매 실행에서, 전체는 월 1회 자동으로 검증한다.

단계검사실패 시 상태
1robots.txt가 피드 경로를 허용하는가robots_blocked
2리다이렉트를 따라가 200이 오는가. 최종 URL을 기록한다http_error / redirected
3RSS·Atom으로 파싱되는가 (200으로 HTML 페이지가 오는 경우를 거른다)not_feed
4엔트리가 1개 이상인가empty
5최신 엔트리가 30일 안인가stale (수집은 함)
6참고 지표: 최근 20개 중 투자 키워드 비율, feed_only 소스의 요약 길이보고서에만 표시

피드 URL이 틀렸거나 비어 있을 때는 홈페이지의 <link rel="alternate" type="application/rss+xml">를 먼저 찾는다. 없으면 /feed, /feed/, /rss, /rss.xml, /atom.xml, /index.xml 순서로 시도해 1~5단계를 통과하는 후보를 찾는다. CSV를 몰래 고치지 않는다. 결과는 verify_report.csv로 내고, --apply를 줄 때만 후보를 CSV에 쓴다 (원본은 .bak). 수집 대상은 ok, redirected, stale뿐이다. 한 번도 작동한 적 없는 소스는 실패 횟수에 넣지 않는다.

8LLM 1차 거르기

LLM은 꼭 필요한가

수집과 폐기만이라면 없어도 된다. 요구한 추출 항목을 채우려면 필요하다. 공인 명단과 해커톤처럼 구조가 있는 소스는 회사명·수상 여부·날짜가 데이터에 이미 있다. 투자 기사도 "금액·라운드·투자사가 하나라도 있는가"는 다국어 정규식으로 판정할 수 있다. 하지만 7개 언어로 된 자유 문장에서 회사명을 뽑는 일, 한국어 한 줄 설명·타깃·카테고리, 한국 유사 서비스 판단은 규칙으로 만들 수 없다.

그래서 규칙이 먼저 걸러 LLM이 볼 양을 줄이고, LLM은 규칙이 못 하는 일만 한다. 설정 llm.backend: none으로 LLM을 끄면 시트에는 원어 제목과 정규식으로 뽑은 금액·라운드만 올라간다. 파이프라인 자체는 그 상태로도 돈다.

작업규칙만으로LLM이 필요한 이유
중복 제거, 최근 7일 창, 유료·robots✔ 된다—
공인 명단·해커톤의 회사명·수상 여부✔ 된다 (구조화 데이터)—
투자 정보 0개인 기사 폐기✔ 된다 (다국어 패턴, 보수적으로)—
자유 문장에서 회사명·금액·투자사 뽑기△ 영어 제목은 일부만독·불·중·일·스웨덴어 기사와 라운드업 기사(회사 여러 곳)
한국어 한 줄 설명, 타깃 고객, 카테고리✗요약과 번역이 필요
수상 기사인지 참가 소개 기사인지△ 키워드는 오탐이 많음문맥 판단
한국 유사 서비스 판단△ 키워드 후보 검색까지만후보 중 실제로 비슷한지 판단

16GB Mac mini에서 쓸 수 있는 로컬 모델

Apple Silicon은 CPU와 GPU가 메모리를 나눠 쓴다. 16GB 중 GPU가 기본으로 쓸 수 있는 몫은 약 2/3(≈10.7GB)이다. 그래서 4비트 양자화 기준 7GB 안팎의 8~10B급 모델이 알맞다. 이 작업은 짧은 원문에서 정해진 칸을 채우는 일이라, 큰 모델의 추론력보다 다국어 독해와 JSON 형식 준수가 중요하다. Ollama는 JSON 스키마로 응답 형식을 강제할 수 있다 (format 인자).

후보 (Ollama 태그)크기판단
qwen3.5:9b≈ 6.6 GB1순위. 중국어·일본어 원문이 많은 이 작업에 강하다. 사고(think) 모드는 끄고 쓴다
gemma4:e4b≈ 7–10 GB비교 후보. 실효 4B급이라 더 빠르지만 추출 정확도는 낮을 수 있다
14B급 (Q4)≈ 9 GB품질 상한 확인용. 메모리가 빠듯하고 속도는 절반 수준
gpt-oss:20b≈ 14 GB제외. GPU 몫을 넘는다

태그와 크기는 2026-11 검색 기준이다. 구현할 때 Ollama 라이브러리에서 다시 확인한다. 모델은 Phase 3에서 정답을 단 50건으로 맞붙여 보고 고른다. 모델 이름은 settings.yaml의 한 줄이다.

작은 모델용 안전장치

  • 요청 1건 = 원문 1건. 출력 칸은 짧게 하고, 카테고리 같은 값은 고정 목록(enum)에서만 고르게 한다. 온도는 0.
  • 회사명과 인용 구절이 원문에 실제로 있는지 코드가 검사한다 (판정 규칙 2·3). 지어낸 이름은 여기서 걸린다.
  • 투자 금액·라운드·투자사는 "원문에 쓰인 것만, 없으면 null"로 한다. 판정은 LLM이 아니라 judge가 한다.
  • 한국 비교는 DB에서 찾은 후보(KR 소스 12개월치 전문 검색 상위 8개)를 근거로만 판단한다. 작은 모델은 한국 스타트업을 잘 모르므로, "없음" 대신 "DB에서 못 찾음"이라고 정직하게 표시한다.
  • 시스템 프롬프트를 고정해 두면 Ollama가 같은 앞부분의 계산을 재사용해서, 원문 부분만 새로 읽는다.

A단계 프롬프트 초안 · 추출·분류

[system]
너는 스타트업 뉴스·명단에서 사실만 뽑아 JSON으로 정리하는 추출기다.
입력은 원문 1건(제목, 요약 또는 본문, 출처, 출처의 공인 유형 signal)이다.

규칙
1. 원문에 쓰여 있는 사실만 적는다. 추측·배경지식으로 채우지 않는다. 없으면 null.
   투자 금액·라운드·투자사는 원문에 명시된 경우에만. "undisclosed/비공개"는 금액 null.
2. 원문에 회사가 여러 곳이면(라운드업 기사, 수상자 목록) mentions에 각각 넣는다.
   특정 회사가 주인공이 아닌 글(시장 동향, 칼럼, 인사, 행사 공지)은 mentions = [].
3. company_name 과 evidence_quote 는 원문의 글자를 그대로 복사한다.
   evidence_quote 는 투자·선정·수상 사실을 보여 주는 30~200자 구절.
4. is_winner: 실제로 상을 받았을 때만 true. 참가·결선 진출 예정·데모 발표는 false.
   대회와 무관하면 null.
5. one_liner_ko: 누구에게 무엇을 해 주는지 한국어 한 문장, 60자 이내, 수식어 없이.
6. keywords_ko: 서비스 핵심을 나타내는 한국어 명사 3~6개. 조사·형용사 없이.
7. category: 아래 목록에서 하나만.
   AI·데이터 | 개발자도구·인프라 | 보안 | 핀테크 | 인슈어테크 | 헬스케어 | 바이오 |
   커머스·리테일 | 푸드·농업 | 모빌리티 | 물류 | 에너지·기후 | 교육 | HR·업무툴 |
   부동산·건설 | 미디어·콘텐츠 | 게임 | 여행·레저 | 하드웨어·로보틱스 | 생활·소비자앱 | 기타
8. country: 본사 국가 ISO 2글자. 원문에서 알 수 없으면 null.

B단계 프롬프트 초안 · 한국 유사 서비스

[system]
해외 회사 1곳과, 한국 스타트업 뉴스 DB에서 찾은 후보 기사 목록을 받는다.
후보 중에 같은 문제를 같은 고객에게 푸는 한국 서비스가 있는지 판단한다.
- 있음: 거의 같은 서비스가 후보에 있다
- 비슷함: 같은 문제를 다른 방식·다른 고객으로 풀거나, 큰 서비스의 한 기능이다
- DB에서 못 찾음: 후보 중에 해당하는 것이 없다
규칙: 후보 목록에 없는 이름은 쓰지 마라. 근거는 후보 번호로 댄다. reason_ko 는 한 문장.

후보는 대상 회사의 keywords_ko를 접두 검색(배달*)으로 OR로 묶어 FTS5에서 찾는다. 조사가 붙은 원문 단어(배달앱을)도 잡힌다. Claude API로 바꾸면 "모델이 아는 한국 서비스"도 근거로 허용할 수 있다 (근거에 from: knowledge 표시).

처리 시간 · 비용 계산기

로컬은 돈 대신 시간이 든다. Mac mini가 월요일 새벽에 몇 시간 일하면 되는 양인지, API로 바꾸면 얼마인지 비교한다. 기본값은 M1 · 16GB 기준 추정치다 (9B 모델 4비트: 생성 약 15~20, 프롬프트 처리 약 150~250 토큰/초). Phase 3 첫 실행에서 실측값으로 바꾼다.

가정: A단계 1건 = 새로 읽는 입력 800 + 출력 350 토큰 (로컬, 사고 끔). API는 시스템 프롬프트를 포함해 입력 2,600 + 출력 550. B단계는 로컬 900+200, API 1,900+400. API 가격은 Batch(50% 할인) 기준이다. Haiku 5.5는 $0.05/$0.25, Sonnet 5.5는 $1/$5 (100만 토큰당, 2026-10 공시가).

10에러 처리와 로깅

격리

  • 소스 단위: 소스 하나의 예외는 fetch_log에 남기고 다음 소스로 넘어간다.
  • 단계 단위: 수집이 통째로 실패해도 이미 쌓인 항목의 LLM 처리와 게시는 진행한다.
  • 행 단위: LLM 응답 1건이 스키마에 맞지 않으면 1회 재시도한다. 3회 실패하면 llm_error로 두고 다음 건으로 간다.
  • 사이클 단위: 게시까지 끝나야 cycle_done을 기록한다. 중간에 끊기면 다음 깨움(다음 날 03:00이나 부팅 직후)이 남은 단계부터 이어서 한다.

소스 장애와 자동 비활성화

로그와 알림

  • ~/startup-radar/data/logs/radar.log: 주 단위로 파일을 바꾸고 12주 보관한다. 한 줄 형식은 시각 레벨 run_id 단계 source_id 메시지.
  • radar status: 최근 실행, 단계별 건수, 비활성 소스, 남은 LLM 작업. SSH로 확인한다.
  • DB 백업: 주간 사이클 시작 전에 SQLite 백업 API로 만들고 8개를 보관한다.
  • 알림: Mac mini 앞에 사람이 없으므로 macOS 알림은 쓰지 않는다. 기본은 시트 맨 위 요약 줄이다. 선택으로 실패 때만 개인 Gmail로 메일을 보낸다 (앱 비밀번호, 표준 라이브러리). Mac mini가 통째로 죽으면 메일도 안 오므로, 요약 줄의 실행 날짜가 오래됐으면 이상 신호로 본다.

11단계별 구현 계획

각 Phase가 끝나면 그 상태로 Mac mini에서 매주 자동으로 끝까지 돈다. Phase 3까지의 결과는 radar export가 CSV로 만들어 iCloud Drive 폴더에 두므로 노트북이나 폰에서 연다. Phase 4부터는 시트로 본다.

Phase 1 · tier 1 RSS·gnews → DB

  • 새 레포, sources.csv 이전 (+3열)
  • config · db · http(예절 전부) · rss · gnews · verify
  • 기사 중복, 최근 7일 창, 자동 비활성화
  • backfill(WordPress 과거 페이지) · install · doctor · status · export
  • 대상: rss 18개(feed_only 5개 포함) + gnews 3개
완료 기준
  • Mac mini에서 사람 손 없이 주간 사이클이 1회 끝났다
  • 검증 보고서에 21개 소스의 상태가 모두 나온다
  • 틀린 URL을 넣으면 3회 뒤 비활성화되고 나머지는 정상이다
  • 두 번 돌려도 항목이 늘지 않는다
  • feed_only 원문 요청이 0건이다

Phase 2 · crawl 소스

  • 스파이크 1일: 6곳의 robots·데이터 위치·로그인 벽
  • 어댑터 등록부, list_diff_html, annual_winners_page(LLM 연결 전까지는 텍스트만 저장)
  • 전용: YC Companies · YC Launches · Devpost · J-Startup · PR TIMES · Startup Nation Finder
  • 12개월 적재, 조용한 고장 감지, fixture 테스트
완료 기준
  • 6개 어댑터가 fixture와 실제 수집을 모두 통과한다
  • Devpost 비수상작이 DB에 0건이다
  • 적재 뒤에는 매주 새 항목만 생긴다

Phase 3 · 규칙 필터 + 로컬 LLM

  • patterns.yaml 규칙 사전 폐기
  • Ollama 백엔드 (+ 같은 인터페이스의 Claude API 백엔드)
  • 프롬프트 A·B, judge, mentions·companies, FTS5 KR 검색, 회사 병합, rejudge
  • 정답을 단 50건으로 qwen3.5:9b와 gemma4:e4b를 비교한다. 참고로 같은 50건을 Haiku로도 돌린다 (약 1센트)
완료 기준
  • 1주치가 M1에서 6시간 안에 사람 손 없이 판정까지 끝난다
  • 50건 중 잘못 폐기 ≤ 2건, 회사명 오류 ≤ 3건
  • 도중에 Ollama를 죽여도 다음 실행이 이어서 한다

Phase 4 · 시트

  • radar sheet init: 탭 4개, 체크박스, 필터 보기
  • '이번 주' 덮어쓰기 전에 ☑ 회수, '관심' 누적
  • 소스 상태·폐기 샘플 탭, 요약 줄, (선택) 실패 메일
완료 기준
  • 월요일 아침 시트에 이번 주 결과가 있다
  • 폰에서 ☑한 것이 다음 주 '관심' 탭에 있다
  • 설치 이후 사람이 실행한 명령이 0개다

그 뒤 2주를 운영해 보고 max_tier: 2로 올린다. rss·gnews는 CSV만으로 늘어난다. crawl은 범용 어댑터 설정으로 먼저 해 보고, 안 되는 곳만 전용 어댑터를 만든다.
